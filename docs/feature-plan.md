# 기능 명세 — 짧은 방명록 (온결)

이번 실습에서 추가하는 저장 기능 하나를 정리한 문서입니다.
수업용 계획 파일이며, 구현/배포는 사용자 확인 후 단계별로 진행합니다.

## 다섯 문장 (기획)

1. 내 홈페이지는 사주(온결)로 나를 이해하도록 돕는 곳이다.
2. 방문자는 별명과 한 줄 메시지를 남긴다.
3. 서버에는 메시지 고유 번호, 별명, 메시지, 저장 시각을 저장한다.
4. 저장 후 화면에는 최근 방명록 글이 최신순으로 보인다.
5. 친구 휴대폰에서도 같은 글이 보이고 재배포 후에도 남아 있으면 완성이다.

## 선택한 조합

- 기능: 짧은 방명록 (과제 예시 3형)
- 배포 서비스: **Vercel** (Functions + 정적 호스팅)
- 데이터 저장: **Supabase** (공통 필수)
- 로그인: 없음 (공개 방명록). 서버 함수가 입력을 검사하고 저장한다.

### Vercel을 고른 이유 vs Netlify

- 현재 프로젝트는 빌드가 없는 순수 정적 사이트(HTML/CSS/JS + vendor/)라 두 서비스 모두 가능하다.
- 사용자가 Vercel을 선택했다. Vercel은 정적 파일 + `api/` 폴더의 Node.js 함수를 기본 구조로 바로 배포할 수 있어 지금 구조에 그대로 맞는다.
- 기존 GitHub Pages 설정은 지우지 않고, 새 Vercel 배포 주소에서 서버 기능을 검사한다.

## 화면 (방명록 UI)

- 위치: 홈(또는 결과 화면 하단)에 "방명록" 섹션 추가. 기존 사주 입력/결과 흐름은 그대로 둔다.
- 입력란: 별명(텍스트), 한 줄 메시지(텍스트), [등록] 버튼.
- 결과 영역: 최근 글 목록(별명 · 메시지 · 상대 시각), 최신순.
- 상태 표시: 저장 중(버튼 비활성), 성공("등록되었습니다"), 실패(사유 표시).

## 저장할 데이터 (Supabase 테이블: guestbook_entries)

| 열 | 타입 | 설명 |
|---|---|---|
| id | bigint (자동 증가) 또는 uuid | 글 고유 번호 |
| nickname | text | 별명 (2~12자) |
| message | text | 메시지 (1~100자) |
| created_at | timestamptz (기본값 now()) | 저장 시각 |

- 공개 테이블이므로 RLS를 켠다. 브라우저는 테이블에 직접 접근하지 않고, 서버 함수(secret key)만 접근한다.

## API (같은 사이트 내)

- `GET /api/guestbook` — 최근 글 목록 조회 (예: 최신 50건). 반환 필드: id, nickname, message, created_at.
- `POST /api/guestbook` — 새 글 저장. 본문: { nickname, message }.

## 검증 규칙 (브라우저 + 서버 양쪽)

- 별명: 2~12자. 비어있거나 범위 밖이면 거절.
- 메시지: 1~100자. 비어있거나 너무 길면 거절.
- 실명/연락처는 받지 않는다.
- 사용자 입력은 HTML로 실행하지 않고 글자로 표시한다 (XSS 방지). 예: `<b>안녕</b>`은 굵게가 아니라 문자 그대로 보여야 한다.
- 수정/삭제 공개 API는 만들지 않는다.

## 최소 완성 (성공 기준)

- 정상 글을 등록하면 Supabase에 실제 저장된 뒤 목록에 최신순으로 보인다.
- 빈 글/너무 긴 글은 저장되지 않고 사유가 표시된다.
- 다른 기기/브라우저에서 같은 글이 보인다.
- 새로고침·재배포 후에도 글이 남는다.
- 저장 실패 시 "완료"로 표시하지 않는다.

## 검사 방법 (직접 확인)

1. "안녕하세요" 등록 → 목록에 보이는지, 휴대폰에서도 보이는지 확인.
2. 빈 메시지 전송 → 거절되는지 확인.
3. `<b>안녕</b>` 입력 → 굵은 글씨가 아니라 입력한 문자 그대로 보이는지 확인.
4. Supabase Table Editor에서 해당 행이 실제로 쌓였는지 확인.
5. 재배포 후 글이 유지되는지 확인.

## 환경 변수 (이름만, 값은 Vercel 대시보드에 직접 입력)

- `SUPABASE_URL` — Supabase 프로젝트 주소
- `SUPABASE_SECRET_KEY` — 서버 전용 secret key (브라우저에 노출 금지)

(실제 코드가 다른 이름을 쓰면 그 이름에 맞춘다. 키 값은 대화/Notion/GitHub에 붙여넣지 않는다.)

## 범위 밖 (이번 버전에서 안 함)

- 로그인, 글 수정/삭제, 신고/관리자 숨김, 반복 등록 제한 → 공개 운영 전 보완 항목.
